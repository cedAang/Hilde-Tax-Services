# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Marketing website for Hilde Tax Services (Arlington, TX tax practice). It's a static site with no framework and no build step: hand-written HTML pages, one stylesheet (`styles.css`), one script (`main.js`). The folder isn't a git repository.

`promo-video/` is a separate Remotion (React/TypeScript) project. It makes a 9:16 promo video and has its own `package.json`; the website doesn't depend on it. Its brief is `PROMPT-remotion-video.md`.

## Commands

Website (needs Python; there are no tests or linter):

```bash
python -m http.server 8765      # preview at http://localhost:8765/index.html
python build-netlify.py         # build netlify-deploy/ + hildetaxservices-netlify.zip
```

**Netlify is a test host only** (https://jocular-trifle-ad7ac8.netlify.app); the site will be hosted on **GitHub Pages** behind the business's own domain, so avoid features that only work on Netlify. GitHub Pages serves static files only: no form handling, no custom headers. Publish only the build allowlist, never the whole folder (keep `secure-tools/`, `promo-video/`, `design-demo/` and any key files out of the repo). The contact/quote form (Netlify Forms) and `netlify.toml` headers will need replacing when the site moves. The test copy is deployed by dragging `hildetaxservices-netlify.zip` (or `netlify-deploy/`) onto https://app.netlify.com/drop. Run the build again after every source change, because the package is a copy, not a link. Never edit files inside `netlify-deploy/`; the build overwrites them.

Promo video (run inside `promo-video/`):

```bash
npm i
npm run dev                     # Remotion Studio preview
npm run lint                    # eslint src && tsc
npx remotion render             # renders to out/
```

## Website architecture

- **The header and footer are copied into each page** (`index`, `services`, `about`, `contact`, plus `tax-intake`, whose header has no CTA buttons). No includes or templates exist, so a nav, phone-number or footer change must be made in all five files. The footer has four columns (brand + IRS badge + social icons, Explore, Services linking to the `#svc-*` anchors, Get in touch with icon discs). The social icons link to Facebook (`https://www.facebook.com/hildetaxservices`) and Instagram (`https://www.instagram.com/hildetaxservices/`), opening in a new tab. TikTok and X still use `#tiktok`/`#twitter` placeholder hrefs until the owner supplies those profile URLs. The icons appear in the utility bar and footer of every page and in the "Follow us" row on contact.html, so change a link in every page. The active nav link is marked with `class="active"` per page.
- **`build-netlify.py` is the publish allowlist.** Only files in its `PAGES` and `ASSETS` lists are shipped. A new page or image must be added there, or it will be missing on the live site. The script also *generates* `thank-you.html` and `404.html` by wrapping a message in `contact.html`'s head, header and footer. Those two pages exist only in the build output, so they pick up header/footer changes from `contact.html` automatically. Links in `404.html` are rewritten to start with `/` because Netlify serves it at any bad URL.
- **`tax-intake.html`** (site header without the two CTA buttons, a 5th copy of the nav; site footer; `styles.css`/`main.js` plus `tax-intake.css` scoped to `.intake` and `tax-intake.js`) is the "Start My Taxes" target linked from every header. It's a 6-step questionnaire. Required fields are marked `*`, and `validate()` blocks Continue with inline messages: legal name (a "Legal name" group with First, Middle (optional) and Last; `buildRecord()` sends them as separate columns and also joins them into "Full legal name", which `Code.gs` needs for the folder name, the required-field check and the email), date of birth, marital status, email, phone, and the mailing address split into street, city, state (a dropdown that starts on Texas) and ZIP (5 or 9 digits), plus a required House / "Apartment, condo or suite" choice that shows the (then required) unit field only for apartments; the "marital status changed in 2025" and "lived or worked outside Texas" Yes/No questions (their details box is required on Yes); spouse name when the status is Married, Legally separated or Widowed (the spouse fields and the "lived apart" question are hidden otherwise); every field of each dependent; and every Yes/No question. On the last step (confirmation checkbox required) it POSTs `{record, botField}` as `text/plain` JSON to the URL in the form's `data-endpoint`. That URL is a Google Apps Script web app (`google-apps-script/Code.gs`, set up per `SETUP.txt`; not in the build allowlist) that appends a row to the "Intake" tab of the owner's Google Sheet, adding a column for any new question title. A time-driven trigger (`checkNewRows`, every minute, created by running `setupTrigger` once) emails the office about each row with an empty "Notified" cell and stamps it (optional Twilio text). It's time-driven because Sheet on-change triggers don't fire for rows a script adds. `buildRecord()` defines the column titles, so renaming a question starts a new column. An empty `data-endpoint` turns submission off. SSN/ITIN: the owner chose to collect **only the last 4 digits** (taxpayer, plus spouse when there is one); the office reaches out to the client for the full number, as the field hint, last step and thank-you screen say. Never add full-SSN or bank-account fields. The Documents step uploads files (PDF, images incl. HEIC, Word, Excel, CSV, TXT; 10 MB each, 20 files, 25 MB total, limits duplicated in `tax-intake.js` and `Code.gs`), sent base64 in the same POST; `doPost` creates a private per-client Drive folder (`<date> <name>` inside "Hilde Tax - Client Files", or the `CLIENT_FOLDER_ID` script property), saves them there, and puts the folder link, file names and any refused files in the row. Folders are never shared with the client.
- **Utility bar + Tax Reminders:** every page has a dark `.utility-bar` above the header (next deadline on the left; Tax Reminders link and social icons on the right). `tax-reminders.html` is rendered by `tax-reminders.js` from **`tax-reminders-data.js`**, the single content file (dates, news, law changes, each with a source URL and an `updated` date). Edit only that file to update the page and the bar's "Next deadline"; past dates hide themselves. It was first filled by web research on 2026-10-30 and is meant to be updated by an automation later. Every page loads `tax-reminders-data.js` before `main.js`.
- **Contact form = Netlify Forms** (`name="appointment"`, honeypot `bot-field`, posts to `thank-you.html`). `main.js` intercepts submission and falls back to a pre-filled `mailto:BernardMbotchak@hildetaxservice.com` when the site runs on localhost or `file:`, or when `data-endpoint` is unset. So a local test never reaches Netlify.
- **`main.js`** is one IIFE that progressively enhances the page: mobile nav drawer, `.reveal` scroll fade-ins (IntersectionObserver), the floating buttons (Share bottom-left; Contact us, which opens the quote modal, and Back to top bottom-right; ported from the school site), the quote modal, form handling, team-photo placeholders, and footer year.
- **Mobile tab bar (`.tab-bar`):** at 900px and below, `main.js` builds a frosted-glass pill nav (Home, Services, About, Start Taxes, Contact) and inserts it right after `.site-header`. It replaces the hamburger menu (hidden on mobile; the drawer markup is still in the HTML for desktop's sake), sits under the logo header, and is `position: sticky` so it stays at the top of the screen while the logo header scrolls away. Reminders isn't a tab because the utility bar above the header links it. Change the tabs in the `tabs` array in `main.js`, not in the HTML. The selected pill is one `.tab-bar__lens` element: tapping another tab makes it swell into a clear glass bubble with a rainbow rim (`.is-moving`), glide to that tab, settle back to green, and then navigate (~0.55s; skipped for reduced motion and modifier-clicks). On desktop (901px and up) the header `.nav` links reuse the same pill look: a light green tint on hover and the soft green pill on the current page, in place of the old underline.
- **Quote modal:** every button with `data-quote` (header Free Quote, Get/Request a Free Quote) opens a `<dialog class="quote-modal">` that `main.js` builds, holding the same `appointment` form (ids prefixed `q-`). Without JS the buttons are plain links to `contact.html`. Keep the static form on `contact.html`: Netlify registers the form from it, and the modal form posts under the same name. If you change the form fields, change both. The modal follows the 3D/glass language ("Quote modal: same 3D + glass language" at the end of `styles.css`): raised card panel with a green ledge (on the top edge for the phone bottom sheet), frosted-glass backdrop, frosted glass close disc, springy pop-in.
- **Services card-deck shuffle:** on `services.html`, `main.js` (Web Animations API) gathers the seven `.svc-row` cards into a stacked deck when `.svc-list` scrolls into view, riffles them, then deals them one by one in random order to their places (~2s). `.svc-list.is-deck` hides the cards until then. It replaces the list's `.reveal` fade, and is skipped for reduced motion and when the URL has a `#svc-*` hash.
- **Home services grid (`.svc-grid`)**: seven `.svc-btn` tiles (icon, name, arrow), each linking to that service's anchor on `services.html` (`#svc-prep`, `#svc-audits`, `#svc-resolution`, `#svc-amended`, `#svc-itin`, `#svc-prior`, `#svc-bookkeeping`). Pure CSS, no JS; flex-wrap keeps a short last row centered.
- **`styles.css`**: design tokens are on `:root` (brand green `#7CB518` / blue `#1B75BC`, Fraunces display + Figtree body, both from Google Fonts). Breakpoints are `900px` and `560px`, at the bottom of the file. Every page gets the fixed `hildetaxservices-bg.jpg` background (`body::before`). The inner pages (`body.page-inner`) reuse the home look: the `.hero` class on their page hero, `.svc-ic` 3D icon discs, `.tile` cards (white with a green-to-blue hairline), and the raised 3D `.btn-primary` / `.btn-tax-intake` / `.btn-ghost`, which are now the default button styles. `.reveal` elements start hidden until JS adds `.in`.
- **Design direction:** one filled primary button per view (green `btn-primary`); everything else uses `btn-ghost`. Cards use one 3D recipe (the "3D depth layer" at the end of `styles.css`, tokens `--card-face`, `--card-rim`, `--card-shadow`, `--card-shadow-up`): white-to-ice face, light blue-grey rim, a 3px green ledge along the bottom (blue on every other card), a ledge shadow plus a soft drop shadow, and a hover lift for cards in a grid. Form fields are inset (pressed in). Reuse those tokens for new cards rather than inventing another shadow. The chrome follows suit ("3D depth: utility bar, header nav, footer" section): on the dark utility bar and footer, social icons, footer icon discs, the Tax Reminders link and the value chips are dark raised discs/pills (`--dark-raised`, `--dark-raised-shadow`) that turn raised green (`--green-raised`) on hover; the header casts a shadow; on desktop the menu sits in a raised frosted track with the current page on a raised green pill. Avoid stacking boxes inside boxes; separate content with spacing and type.

## Design system sandbox (`design-demo/`)

The sandbox holds proposed design enhancements awaiting approval, and isn't deployed (it's not in the build allowlist). `enhance.css` loads after `../styles.css` and holds every proposed change: the fixed h1/h2 scale, `--green-text: #4A730C` for small green text, focus rings, and spacing tokens. It keeps the site's existing colors and fonts. The owner explicitly wants the current brand *enhanced*, not replaced. `index.html` is a copy of the live home page with paths adjusted and a before/after switch; `system.html` documents the tokens with live specimens. Once the changes are approved, merge `enhance.css` into `styles.css` and delete the sandbox.

## Promo video architecture

`src/Root.tsx` registers one composition (1080×1920, 30fps; length is `TOTAL_DURATION` from `Composition.tsx`), which plays the scenes in `src/scenes/` in sequence. `src/theme.ts` mirrors the website's color and font tokens; keep it in sync if the brand colors in `styles.css` change. Static assets (logo, business cards) live in `promo-video/public/`.

## Team photos (`images/`)

The home "Meet Our Team" cards use `images/bernard.jpg`, `images/team-member-2.jpg` and `images/team-member-3.jpg`, which the owner is still collecting from the team. `images/README.txt` lists them. `build-netlify.py` ships any image in `images/` (they're optional, listed in `TEAM_PHOTOS`) and prints a note naming the ones still missing.

## Files not used by the site

All images live in `assets/`. The site uses only `logo-mark.png`, `irs-efile-badge.jpg` and `hildetaxservices-bg.jpg` from it (referenced as `assets/...`; `../assets/...` from `design-demo/`). The rest (`Business Card *.jpeg`, `logo.jpeg`, `irs authorized.jpeg`, the logo/favicon size variants, `bg Image/`) is source material that no page references. If you move the images again, update the pages, `styles.css`, `design-demo/index.html` and `ASSETS` in `build-netlify.py`.
